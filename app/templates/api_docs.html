XShield Ingestion API

Synchronous, application-scoped security telemetry ingestion for web applications and microservices. Events are authenticated using one-way hashed API keys and evaluated via XShield's shared analysis pipeline.

ENDPOINT POST /api/v1/events
AUTHENTICATION X-API-Key: xsh_<token>
CONTENT-TYPE application/json
SIZE LIMIT 16 KiB Max Body

1. Authentication

All requests to /api/v1/events require an X-API-Key request header. Keys are generated via the local management utility:

.\.venv\Scripts\python.exe scripts\manage_applications.py create-api-key --slug my-app

XShield computes and stores a one-way SHA-256 hash of the key in SQLite. Authentications use constant-time comparisons (hmac.compare_digest). Plaintext API keys are never stored in the database or reflected in logs.

2. SecurityEventContract Specification

Payloads must conform to the Phase 1 schema enforced by app.services.event_contract:

Field Type Required Constraints / Allowed Values
event_type string Yes "input_analysis" or "request_observation"
endpoint string No Max 256 characters (e.g. "/search")
http_method string No GET, POST, PUT, PATCH, DELETE
request_id string No Max 128 characters (used for Phase 7 correlation)
input_fields object Yes Map of field names to string values. Max 32 fields, max 10,000 characters combined.
metadata object No Up to 32 key-value entries with explicit trust labels.
retention_mode string No full, truncated, hash_only, redacted, disabled (default: truncated)

3. Request & Response Examples

Example PowerShell Ingestion Request

$headers = @{
    "Content-Type" = "application/json"
    "X-API-Key"    = $env:XSHIELD_API_KEY
}

$body = @{
    event_type     = "request_observation"
    endpoint       = "/user/feedback"
    http_method    = "POST"
    request_id     = "req-89a12c-01"
    input_fields   = @{
        comment = "<script>alert('XSS Probe')</script>"
    }
    retention_mode = "truncated"
} | ConvertTo-Json

Invoke-RestMethod -Uri "http://127.0.0.1:5000/api/v1/events" -Method Post -Headers $headers -Body $body

Success Response (HTTP 201 Created)

{
  "accepted": true,
  "event_id": 142,
  "application": "my-app",
  "status": "accepted"
}

4. Retention & Privacy Modes

XShield normalizes and applies data minimization before writing to disk:

Mode Stored Input Representation Use Case
truncated Caps stored payload to 2,000 characters. Default production monitoring mode.
full Retains entire submitted string (up to 10k). Security research & deep debugging.
hash_only Stores SHA-256 digest of input fields. Compliance environments & zero-PII storage.
redacted Replaces input values with redaction markers. Internal employee portals.
disabled Stores no payload content; persists only metadata and scores. High-velocity telemetry streams.

5. Status Codes Reference

Status Reason Code Explanation
201 Created Accepted Event was validated, analysed by Rule+ML engines, and persisted.
401 Unauthorized Missing/Invalid Key X-API-Key was missing or did not match any active key.
403 Forbidden Revoked/Inactive The key or registered application has been revoked.
400 Bad Request Invalid JSON Request body could not be decoded as JSON.
413 Payload Too Large Max Body Exceeded Request body exceeded Flask's 16 KiB limit.
415 Unsupported Media Non-JSON Content Content-Type must be application/json.
422 Unprocessable Contract Violation Failed schema validation (e.g. unknown fields or input exceeds limits).
500 Server Error Fail-Closed Error Detection or database error; fail-closed behavior guarantees zero bypass.

6. Security Boundaries & Integrity

  • Tenant Derivation: The authenticated API key is the sole authority for application_id. Client requests cannot supply or spoof an application identity.
  • Detector Isolation: Metadata like client IP or request ID is never evaluated as an XSS payload; only explicit input_fields are sent to the detectors.
  • Fail-Closed Guarantee: If the ML model or database fails, the API returns a generic 500 error and never logs an unanalysed event as allow.
  • Local Demonstration Mode: XShield console is unauthenticated in local demonstration mode. API ingestion remains authenticated using X-API-Key.
